# Remora（中文）

> **Remora** — 编码 Agent 的可附加长期记忆层。清理上下文腐烂，锁定关键决策，让你的 AI 搭档跨会话保持记忆。
>
> [English](./README.md)

**Token 是便宜的，心流是昂贵的。**

一种用于长周期 AI 编码 Agent 的开放认知架构——在其他工具触及不到的地方解决上下文腐烂问题。

---

## 你遇到过这种情况吗

项目做到第四天，AI 开始推翻第一天确定的架构。

两周前已经讨论过"为什么不用 Redis"，这一轮会话它又开始建议引入 Redis。

反复纠正同一个错误，但下次开新会话，它又犯。

这不是模型变蠢。这是 **Context Rot（上下文腐烂）**，一种在长周期 AI 协作中必然发生的认知衰减。

---

## 问题的根源比你想的更深

Context Rot 背后其实是两个性质不同的问题：

| 问题 | 本质 | 现有工具的处理 |
|------|------|--------------|
| **信息熵增** | 对话太长，注意力被稀释 | 截断历史、滚动摘要 |
| **记忆漂移** | LLM 悄悄改变对已确定事项的理解 | ❌ 几乎没有工具处理这个 |

Claude Code 有 `CLAUDE.md`，Cursor 有 Rules，但它们都是**静态文本**。没有任何工具在工程层面解决了这个问题：

> *你们三个月前明确讨论过、否决过、并且给出了理由的方案，凭什么让 AI 在六个月后重新提出来？*

**这个仓库的核心是解决第二个问题：通过结构化决策锁定，防止认知漂移。**

---

## 核心设计

### 决策锚定，而非单纯压缩

不只是"摘要历史对话"，而是把对话中的关键判断提炼成**不可漂移的结构化约束**：

```json
{
  "decision": "不引入 Redis",
  "status": "confirmed",
  "rationale": "项目规模小，本地内存缓存足够。否决原因：引入 Redis 增加的运维复杂度远大于性能收益",
  "user_confirmed": true,
  "evidence_msg_ids": [52, 67]
}
```

`rationale` 同时记录了"为什么这样做"和"为什么不那样做"。`user_confirmed: true` 的决策进入硬锚点清单，压缩时不可绕过。这是现有工具普遍缺失的。

### 热 / 温 / 冷三层记忆

```
热记忆（进入 LLM 推理窗口）
  ├── 静态 System Prompt（可缓存）
  ├── 结构化话题摘要索引
  └── 自上次压缩以来的未压缩消息

温记忆（本地数据库，随时可召回）
  └── 完整原始对话 + FTS5 全文索引

冷记忆（跨项目经验库，Phase 3）
  └── 踩坑记录 + 可复用规则
```

压缩是有损的，但原始记录永不丢失。错误可逆。

### 话题化高内聚低耦合

对话历史不是一张混乱的消息网，而是一幅**结构化记忆地图**。每个话题包含完整的决策脉络，通过显式依赖关联，而不是让信息散落在数百条消息的各个角落。

### 无状态子代理执行

代码修改委派给**用完即焚**的隔离子代理（Git Worktree），主干认知不被执行过程污染，变更差异由用户确认后再应用。

## 现有工具做了什么，没做什么

| 能力 | Claude Code | Cursor | Remora |
|------|:-----------:|:------:|:------:|
| 跨会话记忆 | CLAUDE.md（静态） | Rules（静态） | ✅ 动态结构化 |
| 否定性决策记录 | ❌ | ❌ | ✅ |
| 决策漂移防护 | ❌ | ❌ | ✅ |
| 原始对话可召回 | ❌ | ❌ | ✅ |
| 代码执行隔离 | ✅ | 部分 | ✅ |
| 压缩可信度校验 | ❌ | ❌ | ✅ |

---

## Remora 明确不做的事

- **不做通用记忆系统**。Remora 专为长周期 Coding Agent 的决策管理设计，不服务聊天机器人、个人知识库或通用问答场景。
- **不做自带模型**。不训练记忆模型，不内置任何 LLM，完全依赖云端 API（DeepSeek、Kimi、OpenAI 等）进行推理。
- **不做代码生成**。这是记忆层，不是 Coding Agent 本身。它附加在现有 Agent（如 Claude Code、Cursor）之上，只负责管理决策历史和上下文结构，不直接生成或修改代码。
- **不追求全自动话题切分**。手动打标是经过深思熟虑的设计选择，不是临时妥协。让用户显式管理话题边界，远比让 LLM 自动猜测更可靠。
