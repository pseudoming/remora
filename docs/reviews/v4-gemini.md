## 盲区一：Git Worktree 的"脏工作区悖论"

* **灾难爆发**：Git Worktree 是基于当前仓库的 `HEAD` 创建的，它**绝对看不见** IDE 里未提交的"脏改动"！子代理在沙箱里面对的是修改前的老代码，产生严重幻觉。更恐怖的是，如果子代理基于老代码给出补丁并试图 merge 回主工作区，**极大概率会静默覆盖掉未提交的心血**。
* **V5 修正决断：WIP 物理快照与差异剥离（Patching）**

```bash
# 启动时：镜像脏状态
STASH_HASH=$(git stash create)  # 生成包含脏代码的悬空 Commit
git worktree add ../sandbox $STASH_HASH

# 回写时：提取纯补丁
git diff $STASH_HASH HEAD > agent.patch  # 沙箱内
git worktree remove ../sandbox --force
git apply agent.patch  # 主工作区，以未提交形式出现供 Review
```

## 盲区二：热记忆的"时间黑洞"（上下文逻辑断层）

* **灾难爆发**：热记忆被硬编码为"最近 3 轮"。当 Token 阈值允许积累 30 轮才触发压缩时，第 4 轮到第 22 轮的对话既没有被压缩成 Topic 摘要，也不在"最近 3 轮"里——这是一个彻底的**盲区**。大模型会患上"中期记忆丧失症"。
* **V5 修正决断：动态水位线缓冲**

热记忆的动态部分必须是：**`[自上一次压缩水位线 (Watermark ID) 之后产生的所有未压缩原始消息]`**。只有当这个动态缓冲池撑爆了 70% 的阈值，才触发压缩并将水位线前移，绝对不能截断丢失。

## 盲区三：意图硬拦截的"误杀风暴"（破坏开发者心流）

* **灾难爆发**：开发者说"你刚才写的这行正则**不对**"或"新加的字段和我们**之前**定好的入参类型不匹配"——这些话是在纠正"当前代码逻辑"，而非质疑"历史记忆"。一旦正则触发，系统中断 Debug 心流去翻历史记录，回答牛头不对马嘴。
* **V5 修正决断：极轻量 LLM 语义路由（Semantic Router）**

正则只作为"触发器"。命中后，丢给一个极廉价的模型（如 DeepSeek-Flash），使用极简 Prompt：*"用户是在纠正【当前代码错误】，还是在质疑你遗忘了【历史事实/过去做过的决议】？只输出 CODE 或 MEMORY。"* 只有输出 MEMORY 时，才真正触发 FTS5 检索。

## 盲区四：`associated_files` 的"关联爆炸与路由中毒"

* **灾难爆发**：全局重构任务修改了 80 个文件，全部被塞入 Topic 锚点。第二天修复 `auth.py` 的小 Bug，因为 `auth.py` 也在那 80 个文件里，系统把庞大且无关的"全局重构"摘要硬塞进上下文。久而久之系统患上"认知过敏症"。
* **V5 修正决断：事后锚定与抽象阈值**

1. **事后锚定**：等子代理执行完，把真正被修改（Mutated）的文件写入关联，只是读取（Explored）的文件不写。
2. **抽象阈值**：如果单次子任务修改文件超过 N 个（如 5 个），不记录具体文件路径，而是向上抽象记录 `directory: ["src/"]` 或打 `tag: global_refactor`。

---

## 盲区五：FTS5 检索的"时序乱序（Chronological Hallucination）"

* **灾难爆发**：FTS5 基于 BM25 相关度排序。如果历史时间线是 "Day 1 Redis → Day 2 换本地缓存 → Day 3 切回 Redis"，返回顺序可能乱序为 [Day 2, Day 1, Day 3]。大模型面对时间线错乱的历史碎片，根本理不清逻辑因果，直接发生严重幻觉。
* **V5 修正决断：强制召回后排序（Post-Retrieval Reordering）**

Memory Bus 必须增加最后一道防线：从 SQLite 取出 Top K 相关记录后，在注入 Prompt 之前，**必须在代码层强行按 `message_id` 或 `timestamp` 重新升序排列（ASC）**。把线性的因果律还给大模型。

---

## 架构师的最终判决

这 5 个问题（脏状态物理丢失、缓冲池截断、正则误杀、关联爆炸、时序倒错）任何一个爆发，都足以让开发者愤怒地按下 `Ctrl+C`。

但只要将这 5 个补丁（WIP Patching 同步、水位线动态缓冲、语义路由旁路、抽象关联阈值、强行时序重排）焊入系统，整个 V5 架构将完成从"静态坚固"到"动态无敌"的终极蜕变。

**消化完这 5 个点，将它们作为约束条件写入设计准则中。在那之后，无需再出 V5 文档了。打开终端，敲下 `git init` 吧！真正的战场在代码里。**
